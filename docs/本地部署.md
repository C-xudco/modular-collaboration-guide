# 下载后在自己的 Codex 使用

## 一次安装

1. 安装 Node.js 24 或更新版本，并登录自己的 Codex。
2. 下载项目 ZIP 解压，或克隆仓库，在项目目录打开终端。
3. 执行 `node scripts/install-local.mjs --register`。
4. 重新打开 Codex 对话，使用 `$modular-collaboration-guide`。

不需要作者授权、云端账号或 API 密钥。自己在 Codex 的对话、提炼和深入建议仍按自己账户计量。Skill 指令和读取的记忆进入模型上下文，不能承诺完全零 token 消耗。

自动接入找不到 Codex CLI 时，安装程序给出真实本机路径的命令和配置片段。复制完整命令，或在 MCP 设置中添加 stdio 服务：命令为本机 Node，参数为项目 local/server.mjs 的绝对路径。也可将输出的小节合并到 ~/.codex/config.toml，保留已有小节，不替换整份配置。

Skill 默认安装到 CODEX_HOME/skills/modular-collaboration-guide；未设置 CODEX_HOME 时用 ~/.codex/skills/modular-collaboration-guide。如客户端要求其他目录，手动复制本项目 skills/modular-collaboration-guide 文件夹即可。

## 面板

执行 `node local/server.mjs --web`，打开显示的地址（默认 http://127.0.0.1:4173/）。保持程序运行。它与 Codex 自动启动的 stdio 服务共享本地档案，有版本检查；无需启动开发预览 5173。

- 开始协作：填写目标、采用并修改建议，复制带所选背景的草稿到 Codex。
- 方法库：修改、启停、新增和恢复版本。
- 我的记忆：编辑、确认候选、停用、纠正冲突、恢复版本、导入导出。
- 当前任务：选择本任务使用的方法和记忆。

网页不能直接发送到 Codex；深入建议也先复制再主动发送。只有支持 MCP Apps 和消息发送的内嵌面板才能直接发送；不支持时用网页管理。

## 数据、备份与迁移

数据路径见 README。仓库和 Skill 包不含个人档案。用 COLLABORATION_DATA_DIR 分开档案时，MCP 和网页须使用同一设置才能共享。

JSON 迁移当前条目，导入记忆保持候选，不自动覆盖原条目。Markdown 供阅读。完整备份：先停止使用该数据库的所有 Codex / 网页进程，再备份整个数据目录（含数据库及可能的 WAL 文件）。不要在写入期间只复制单个文件。卸载不自动删除个人数据。

旧云端档案可自行导出 JSON 并在本地导入，不会自动下载。若同时安装云端和本地版，关闭本次不使用的一套工具，避免误选档案。

## 升级与故障

备份数据，更新项目，再运行 `node scripts/install-local.mjs --register --update`。原 Skill 会备份。项目路径改变时重新接入 MCP。

- 拒绝连接：重新运行 `node local/server.mjs --web` 并保持终端打开。
- 端口占用：改用 `node local/server.mjs --web --port 4174`。
- 找不到 Node：添加到客户端 PATH，或使用输出的绝对路径。
- 版本冲突：刷新核对后保存，不强行覆盖其他窗口。
- 网页无法读取：回到首页刷新建立本地会话 Cookie。MCP 不使用浏览器 Cookie。
- 没有内嵌面板：使用本地网页，工具与数据存储仍可用。

服务只监听本机，不为多人远程共享设计。本地数据库由当前系统用户文件权限保护。
